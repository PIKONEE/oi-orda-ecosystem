## Технологии и факты ядра
- Карта — **Leaflet** локально (`content/lib/`). База — **физические тайлы**
  (рельеф/реки, Esri World Physical Map) в `content/tiles/{z}/{x}/{y}.jpg`, офлайн.
  Тайлы: **весь мир z2–3** + **регион Казахстана z4–6**. Два слоя: базовый —
  весь мир с `maxNativeZoom:3` (на zoom 4–6 апскейлит z3, поэтому пустых
  «голубых» краёв нет **ни на каком масштабе**); детальный — регион
  (`bounds [[37,45],[58,90]]`, `minNativeZoom:4`) даёт чёткость по Казахстану
  поверх базового. Жёсткий `maxBounds` = мир (viscosity 1.0); нижний зум
  авто-ограничивается (`capWorldZoom` через `getBoundsZoom(world,true)` на boot и
  resize), чтобы мир **всегда заполнял экран** — при отдалении нет пустых краёв.
  Контролы зума — **справа сверху** (не перекрывают подпись эпохи слева). Тонкие
  совр. границы — из `base_geo.js`.
- **Территории (`data/territories.js`) показываются ТОЛЬКО когда было казахское
  государство** — это историческая принципиальная правка: territory рисуется лишь
  для Казахского ханства/жузов (1465–1821) и советской республики → совр. Казахстана
  (1920→). **До ханства** (саки…монголы) и **в составе Российской империи**
  (1822–1920) `terr:null` — территорию НЕ рисуем (казахского государства не было).
  Границы — точные, из **historical-basemaps** (Quazaq Khanate 1530/1700/1715):
  `khanate_early`, `khanate_peak`, `zhuzes`; западную степь Младшего жуза (датасет
  ошибочно держит её за Ногайской ордой и после её распада) доклеиваем через
  `shapely`-union в `tools/extract_territories.py` (ханство шло до р. Урал, ≠ совр. РК).
  `modern` рисуется по **точной границе РК из `base_geo.js`**. Ханство/жузы ≠
  современный Казахстан (другой запад, юг по Сырдарье). Генерация —
  `python tools/extract_territories.py`.
- webview2-оболочка отдаёт контент локальным http-сервером (расшифровка в памяти),
  сборка шифрует **весь** `content/`. Поэтому `fetch`/Leaflet/картинки работают; но
  данные грузим через `<script>`-глобалы (надёжно и на Android).
- `_secret.py` (v4) — только публичный ключ; `python -m product_core.keygen embed 4`
  (на этой машине: префикс `PYTHONIOENCODING=utf-8` при редиректе).

## Структура контента
```
content/
├── index.html  app.css  app.js
├── lib/        leaflet.js, leaflet.css
├── assets/     fonts.css, fonts/ (PT Serif + Inter), icon
├── locales/i18n.js          ← строки UI RU/KZ
├── tiles/{z}/{x}/{y}.jpg   ← физические тайлы карты (офлайн)
└── data/
    ├── eras.js              ← window.ERAS (периоды: from, terr, color, names) + CATS + EVENTS=[]
    ├── territories.js       ← window.TERRITORIES: {terrKey:{name,geometry,approx?}} (GeoJSON)
    ├── base_geo.js          ← window.BASE_GEO: контуры стран региона (тонкие границы)
    └── events_<era>.js      ← события: window.EVENTS.push({...})
```

## Как добавить событие (контент отделён от кода!)
Допиши один объект в подходящий `content/data/events_<era>.js`:
```js
{id:"unique-id", year:1731, lat:49.0, lng:57.0, era:"russia", cat:"treaty",
 titleRu:"...", titleKz:"...", descRu:"...", descKz:"..."}
```
- `year` — число (до н.э. = отрицательное); **период определяется по году
  автоматически** (метка покажется в своём периоде). `cat` — ключ из `CATS`.
  `lat/lng` — реальные координаты (точные если известны, иначе приблизительные по
  источникам). Все 4 текста (RU+KZ) обязательны. Поле `era` — метка-тема (не влияет
  на логику; период считается из года).
- Новый период — запись в `ERAS` (`from`, `terr`, цвет, названия). Несколько периодов
  могут делить одну `terr`. Территория — в `TERRITORIES` (GeoJSON-геометрия).
- Новая категория — запись в `CATS` (ключ, цвет, RU/KZ). Метки/фильтр/легенда
  строятся из конфига автоматически — код менять не нужно.
- После изменений: **`node tools/validate.js`** — проверит поля, типы, координаты
  (в пределах региона), известную `cat`, наличие RU+KZ и покажет число событий по периодам.
