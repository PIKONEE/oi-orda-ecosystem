# 🏛 Экосистема продуктов Oi-Orda — как создавать продукты

> Это **главный документ-договорённость** (single source of truth) о том, как
> устроены все продукты и как создавать новые так, чтобы они были частью одной
> экосистемы, **все защищены и активируются по ключу**, и не возникало
> неразберихи.
>
> Если ты (или Claude) создаёшь новый продукт — сначала прочитай этот файл.
> Технические детали API смотри в [README.md](README.md), но **при расхождении
> верен этот документ и реальный код в `product_core/`, а не примеры в README.**

---

## 0. Главное правило (prime directive)

**У всей экосистемы один хребет — `product-core`. Каждый продукт подключается к
нему, а не делает своё.**

```
                ┌──────────────────────────────┐
                │        product-core          │   ← ОДИН на всё
                │  • один формат ключа (v3)    │
                │  • одна оболочка (WebView)   │
                │  • один keygen (master.key)  │
                │  • один билд (Win + Android)  │
                └──────────────────────────────┘
                  ▲        ▲        ▲        ▲
        ┌─────────┘   ┌────┘   ┌───┘    ┌───┘
   ┌────┴────┐  ┌─────┴───┐ ┌──┴────┐ ┌─┴──────┐
   │ плакаты │  │ 3D-модели│ │словарь│ │матлаб …│   ← ТОЛЬКО контент + конфиг
   └─────────┘  └─────────┘ └───────┘ └────────┘
```

Что это значит на практике:

1. **Никаких самописных оболочек.** Окно, WebView, экран активации, защита от
   копирования, проверка лицензии — это всё уже есть в `product-core`. Новый
   продукт их не пишет заново.
2. **Один формат ключа и один `master.key`** на все продукты. Один генератор
   ключей обслуживает всю линейку.
3. **Каждый продукт = контент + `product.json` + `_secret.py`.** Всё, что
   отличает один продукт от другого, — это его контент и конфиг.
4. **Защита — не опция.** Продукт без `_secret.py` и активации не выпускается
   (см. §6). Единственное исключение — внутренние демо с явным
   `skip_activation`.

Дизайн (цвета, вёрстка, UX) у каждого продукта может быть свой — экосистему
держит **общая архитектура и общая защита**, а не одинаковый вид.

## 1. Ментальная модель за 30 секунд

- **`product-core` — это библиотека-хребет**, а не фреймворк. Она не диктует, как
  писать продукт. Она даёт: оболочку-контейнер, лицензирование, генератор ключей,
  сборку под Windows и Android.
- **Продукт — это контент в `content/` + описание в `product.json`.** Логика
  (графики, 3D, словарь, карта, игра) живёт в HTML/JS или в твоём Python-коде.
- **Ключ привязан к устройству и к продукту.** Один мастер-секрет → у каждого
  продукта свой производный секрет → утечка одного продукта не ломает остальные.

## 3. Два архетипа продукта

Любой будущий продукт попадает в один из двух типов. Сначала определи тип — от
этого зависит всё остальное.

### Архетип A — WebView-продукт (контент на HTML/JS/CSS) ← по умолчанию

Подходит почти всему: интерактивные плакаты, 3D-модели (GLB во viewer'е),
3D-конструктор фигур, визуализатор графиков, карты (историческая, музыкальная),
словарь, музыкальная энциклопедия, логопедические игры, тренажёры.

Ты пишешь **только** `content/index.html` (+ свои JS/CSS/ассеты). Оболочка
`product-core` сама даёт окно, активацию, защиту и сборку под Win + Android.

`main.py` — буквально две строки. Это **предпочтительный** архетип: один и тот же
код контента работает и на Windows, и на Android без изменений.

### Архетип B — произвольный Python-продукт (Flask, SQLite, своя логика)

Подходит «облегчённым версиям Oi-Orda» (кабинет психолога, кабинет соцпедагога) и
всему, что по сути серверное приложение или сложная Python-логика.

Ты пишешь свой код как обычно и добавляешь **блок лицензии из 5 строк** (§5-Б).

> ⚠️ **Честное предупреждение про Android для архетипа B.** WebView-оболочка
> `product-core` под Android рассчитана на статический контент (архетип A).
> Flask-приложение (сервер на Python) на Android из коробки не собирается. Для
> кабинета психолога/соцпедагога есть два пути:
> 1. **Windows-first**: на Windows — Flask в фоне + окно (архетип B), Android
>    позже.
> 2. **Перенести «облегчённую» версию в статический WebView** (архетип A): если
>    тестам и справочнику вузов не нужен сервер, их логику можно сделать на
>    клиентском JS — тогда продукт едет на Android как все остальные. Для
>    «облегчённых без ИИ» версий это чаще всего реально и **рекомендуется**.

### Как выбрать

```
Контент рисуется в браузере (HTML/Canvas/WebGL/three.js)?
   └─ ДА  → Архетип A (WebView). Это 90% продуктов.
   └─ НЕТ, нужен Python-сервер / тяжёлая БД / десктоп-GUI?
            └─ ДА → Архетип B. Но сначала спроси: а нельзя ли архетипом A?
```

## 4. Канонічная структура продукта

Любой продукт (оба архетипа) выглядит так. **Эта структура — обязательна.**

```
мой-продукт/
├── product.json          ← конфиг продукта (единственное, что описывает продукт)
├── _secret.py            ← секрет продукта (СГЕНЕРИРОВАН keygen'ом, НЕ коммитить)
├── main.py               ← A: 2 строки оболочки. B: твой код + блок лицензии
├── CLAUDE.md             ← инструкция для ИИ-ассистента по этому продукту
├── assets/
│   └── icon.svg          ← иконка (→ из неё билд сделает .ico для Windows)
└── content/              ← ВЕСЬ контент продукта
    ├── index.html        ← точка входа (entry_html)
    ├── locales/          ← ru.json, kz.json (двуязычность — обязательна, §6)
    └── ...               ← твои js/css/ассеты/данные
```

Файлы, которые **нельзя коммитить в открытый репозиторий** (они в `.gitignore`):

| Файл | Почему |
|---|---|
| `master.key` | мастер-секрет; утечка = все ключи скомпрометированы |
| `_secret.py` | производный секрет продукта |
| `keys.db` | база выданных ключей (привязка клиент ↔ устройство) |
| `license.dat` | активированная лицензия пользователя |

## 5. Точная интеграция (реальный API)

> ⚠️ **Важно.** В `README.md` в разделах «промпты для Claude» API указан
> **неверно** (`configure(mask, kdata, id)`, `activate()`, `get_status()` —
> таких функций нет). Ниже — **реальный** API из `product_core/licensing.py`.
> Используй только его.

### Что генерирует keygen в `_secret.py`

```python
PRODUCT_ID = 5
_MASK  = [ ... 32 байта ... ]
_KDATA = [ ... 32 байта ... ]
def get_secret():
    return bytes((a ^ b) & 0xFF for a, b in zip(_MASK, _KDATA))
```

То есть `_secret.py` экспортирует `PRODUCT_ID` и функцию `get_secret()`.

### Архетип A — main.py (две строки, и всё)

```python
from product_core.shell import run
run(__file__)
```

Оболочка сама: прочитает `product.json` и `_secret.py`, вызовет
`licensing.configure(...)`, покажет экран активации, после активации загрузит
`content/index.html`. **Тебе в Python писать больше нечего.**

Контент общается с оболочкой через JS-мост `core.*` (одинаковый на Win и Android):

```html
<script src="qrc:///qtwebchannel/qwebchannel.js"></script>
<script>
  // получить мост
  if (typeof qt !== 'undefined') {
    new QWebChannel(qt.webChannelTransport, ch => { window.core = ch.objects.core; });
  } else if (typeof core !== 'undefined') {
    window.core = core;            // Android: уже доступен
  }
  // core.getDeviceId()  → string (16 hex)
  // core.getStatus()    → JSON-строка {valid, reason, variant_id, expires_at, days_left}
  // core.activateKey(k) → вызовет onActivationSuccess(msg) / onActivationError(msg)
  // core.log(msg)       → запись в лог оболочки
</script>
```

Экран активации и проверка лицензии — внутри оболочки; контенту обычно не нужно
вызывать `activateKey` самому. `getStatus()` полезен, если хочешь показать в
контенте остаток дней или включить функции по `variant_id`.

### Архетип B — main.py (твой код + блок лицензии)

```python
# === Лицензия product-core (вставить в самое начало) ===
from product_core import licensing
from product_core.device_id import get_device_id
from _secret import PRODUCT_ID, get_secret

licensing.configure(get_secret(), PRODUCT_ID, app_name="my-slug")

if not licensing.is_activated():
    print("Device ID:", get_device_id())          # клиент сообщает этот ID
    ok, msg = licensing.activate_key(input("Ключ: ").strip())
    print(msg)
    if not ok:
        raise SystemExit(1)
# === Дальше — ТВОЙ код: Flask, PySide6, SQLite — что угодно ===
```

Реальные функции (`product_core/licensing.py`), бери **эти имена**:

| Функция | Сигнатура | Что делает |
|---|---|---|
| `configure` | `configure(secret: bytes, product_id: int, app_name="...")` | задать секрет продукта |
| `configure_obfuscated` | `configure_obfuscated(mask, kdata, product_id, app_name="...")` | то же, но из `_MASK`/`_KDATA` напрямую |
| `is_activated` | `() -> bool` | есть ли действующая лицензия |
| `activate_key` | `(key: str) -> (bool, str)` | активировать ключ → сохранить `license.dat` |
| `get_license_status` | `() -> dict` | `{valid, reason, variant_id, expires_at, days_left}` |
| `get_activated_variant` | `() -> int \| None` | какой вариант активирован |
| `get_device_id` | `() -> str` | ID устройства (из `product_core.device_id`) |

> Имена `activate` / `get_status` (без суффиксов) **не существуют** — это ошибка в
> примерах README. Правильно: `activate_key`, `get_license_status`.

## 6. Защита и активация — обязательные правила

Чтобы «все продукты были защищены» не на словах, это чек-лист релиза. Продукт
**не выпускается**, пока не выполнено:

- [ ] есть `_secret.py`, сгенерированный `keygen embed <product_id>`;
- [ ] `product.json` → `security.skip_activation = false`;
- [ ] `security.anti_copy = true` (запрет копирования/контекстного меню в WebView);
- [ ] `security.flag_secure = true` (на Android запрещает скриншоты/запись экрана);
- [ ] активация проверена вживую: без ключа продукт показывает экран активации,
      с правильным ключом — открывает контент, ключ с чужого устройства —
      отклоняется;
- [ ] продукт двуязычный (RU/KZ) — это стандарт линейки (см. плакаты, матлаб);
- [ ] `product_id` и его `variant_id` внесены в реестр §7.

**Почему это безопасно:** ключ = `payload(7) + HMAC(секрет_продукта, payload +
device_id)[:8]`, в base32 → `XXXX-XXXX-XXXX-XXXX-XXXX-XXXX`. Секрет продукта
выводится из `master.key` как `HMAC(master, "product:"+id)`. `master.key` есть
только у тебя; в сборку попадает лишь обфусцированный производный секрет.
`license.dat` шифруется ключом, производным от `device_id`, поэтому не переносится
на другое устройство. Защита одинаково работает на Windows и Android (Kotlin-порт
`android_shell/Licensing.kt` использует те же `_MASK`/`_KDATA`).

## 7. Реестр продуктов и вариантов (single source of truth)

`product_id` (0–255) = **тип продукта**. `variant_id` (0–255) = предмет / язык /
категория внутри продукта. Это позволяет одним ключом активировать, например,
плакаты по конкретному предмету.

> **При создании нового продукта впиши его сюда первым делом** — чтобы id не
> пересекались. Это и есть защита от неразберихи.

### Продукты

| product_id | slug | архетип | продукт |
|---:|---|:--:|---|
| 1 | `interactive-posters` | A | Интерактивные плакаты (все предметы как варианты) |
| 2 | `smart-dictionary` | A/B | Умный словарь (англ. и др.) |
| 3 | `3d-models` | A | 3D-модели и 3D-конструктор фигур |
| 4 | `interactive-map` | A | Интерактивные карты (история, музыка, география) |
| 5 | `math-tools` | A | Матлаборатория: графики + вероятности |
| 6 | `music-encyclopedia` | A | Музыкальная энциклопедия (карта/лента/слух) |
| 7 | `speech-therapy` | A | Логопедические игры (планшет/Android) |
| 8 | `oi-orda-lite` | B→A | Облегчённый Oi-Orda (психолог / соцпедагог) |
| 9–255 | … | | будущие продукты |

> Спорные случаи решены так (можно поменять, но зафиксируй здесь):
> - **3D-конструктор геометрических фигур** — это вариант продукта `3d-models`
>   (он визуальный/WebGL), а не отдельный продукт.
> - **Историческая карта** и **карта музыкальных традиций** — варианты
>   `interactive-map`.
> - **Кабинет психолога и соцпедагога** — один продукт `oi-orda-lite` с двумя
>   вариантами (псих=0, профориентация=1), а не два продукта. Если разводить
>   лицензии по кабинетам удобнее — сделай два product_id.

## 8. Пошагово: создание нового продукта

```bash
# 1. Скопировать шаблон
cp -r product-core/templates/new_product/  мой-продукт/

# 2. Заполнить product.json: product_id (из реестра §7), slug, name, variants
#    + впиши продукт в реестр §7

# 3. Один раз на машине разработчика — мастер-секрет (если ещё нет)
cd product-core
python -m product_core.keygen init                # создаёт master.key (БЭКАП!)
pip install -e .                                   # ставит product_core

# 4. Сгенерировать секрет продукта
python -m product_core.keygen embed 5 > ../мой-продукт/_secret.py

# 5. Написать контент
#    Архетип A: content/index.html (+ js/css/locales)  — main.py не трогаешь
#    Архетип B: свой main.py со своим кодом + блок лицензии §5-Б

# 6. Запустить в разработке
cd ../мой-продукт && python main.py

# 7. Собрать дистрибутивы (Windows + Android одной командой)
python -m build мой-продукт/                       # оба
python -m build мой-продукт/ --windows             # только Win
python -m build мой-продукт/ --android             # только Android
#   → мой-продукт/builds/windows/  и  builds/android/

# 8. Выдать ключ клиенту (клиент называет свой Device ID с экрана активации)
python -m product_core.keygen gen 5 0 42 --device A3F2B1C8E4D71029 --months 12 --note "Школа №5"
#                                       │ │  │
#                             product_id┘ │  └ client_id
#                               variant_id┘
```

## 10. Брендинг и нейминг (договорённость)

- **Бренд экосистемы:** Oi-Orda. Поле `publisher` в `product.json` — `"Oi-Orda"`
  (сейчас по умолчанию `"DigiTouch"` — стоит поменять на Oi-Orda для единства).
- **Технический namespace Android:** `kz.digitouch.<slug>` (оставлен как в коде,
  чтобы не ломать уже выпущенное; менять централизованно, если решишь).
- **slug** — короткий латиницей через дефис: `math-tools`, `3d-models`.
- **Двуязычность RU/KZ** — обязательна во всех продуктах (это лицо линейки).

> Единственное, что стоит подтвердить отдельно: оставляем технический namespace
> `kz.digitouch.*` или переводим на `kz.oiorda.*`. На защиту и архитектуру это не
> влияет — только на идентификатор пакета Android.

## 11. Работа с Claude (ИИ-ассистентом)

В каждой папке продукта лежит `CLAUDE.md` (шаблон —
`templates/new_product/CLAUDE.md`). Когда просишь Claude доработать продукт, он
читает этот файл и знает контракт: какой архетип, какой `product_id`, что
`_secret.py` трогать нельзя, какой реальный API у лицензирования.

Готовые корректные промпты — в `templates/new_product/CLAUDE.md`. **Не используй
промпты из README.md как есть** — там устаревший API (см. предупреждение в §5).

## TL;DR

1. Один хребет — `product-core`. Продукт = `content/` + `product.json` +
   `_secret.py`. Своих оболочек не пишем.
2. Архетип A (WebView) по умолчанию; B (Python/Flask) — для «облегчённого
   Oi-Orda».
3. Защита обязательна: `_secret.py` + активация + anti-copy + flag_secure,
   проверено вживую (§6).
4. `product_id`/`variant_id` — из реестра §7, новый продукт вписывается туда
   первым делом.
5. Реальный API — `configure / activate_key / get_license_status` (§5), а не то,
   что в README.
6. Срочно: защитить 3D-модели и внести матлабораторию в экосистему (§9).
