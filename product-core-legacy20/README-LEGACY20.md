# LEGACY-20 — запасное ядро с коротким ключом

Копия боевого ядра, в которой активация сделана **по-старому**: ключ из
20 символов `XXXX-XXXX-XXXX-XXXX-XXXX` вводится с клавиатуры, **QR-сканера нет**.

Живёт в ветке `legacy-20char` и **никак не влияет** на основную сборку —
там ядро `product-core` (v4/QR) остаётся без изменений.

## Чем отличается от боевого ядра

| | product-core (боевое) | product-core-legacy20 |
|---|---|---|
| Ключ | `OL1-…`, 142 символа | 20 символов |
| Ввод | QR-камерой, из файла или руками | только руками |
| Подпись | Ed25519 (асимметричная) | HMAC-SHA256 (симметричная) |
| Ключ подписи | приватный только у нас | секрет лежит **внутри APK** |
| Контент в APK | зашифрован (AES-256-GCM) | **открытый** |
| Камера, ML Kit | нужны | не нужны (APK меньше ~10 МБ) |

**Важно:** в этой схеме короткий ключ физически не может нести ключ шифрования
контента, поэтому контент не шифруется, а секрет подписи лежит в APK. Значит,
распаковав APK, контент можно извлечь. Использовать только там, где удобство
ввода важнее защиты контента.

## Как выдать ключ

```
python keygen_legacy20.py products
python keygen_legacy20.py gen --product 3 --device A3F2B1C8E4D71029 --client 42 --months 12
python keygen_legacy20.py gen --product 9 --variant 1 --device A3F2B1C8E4D71029 --client 7 --months 12
```

Device ID клиент видит на экране активации. Секрет подписи выводится из
мастер-ключа экосистемы (`ecosystem.keys` или переменная `OI_CONTENT_MASTER`)
той же формулой, что и при сборке, — поэтому ключи подходят к APK без
обмена файлами.

Ключ привязан к устройству и к продукту: на другой доске или в другом
продукте он не сработает. Для многопредметных продуктов `--variant 0`
открывает все предметы, остальные значения — конкретный предмет.

## Как собрать

Сборка идёт в CI по ветке `legacy-20char` — workflow `build-legacy20`,
артефакт `oi-orda-apks-legacy20`. Локально:

```
cd product-core-legacy20
python -m build ../products/3d-models --android
python -m build ../products/virtual-stands --android
```
